These are owned synthetic qualification hosts, not the three planned external open-source showcases. Each starts with an explicit business boundary and carries only its actual evidence.

## React/TypeScript helpdesk: full transformation and browser journey

**Before:** a plain ticket page and tenant-scoped domain functions, with no AE imports or assistant. [Original host](../fixtures/existing-react-helpdesk).

**AE change:** `react-helpdesk@1.1.0` records source hashes and proposes a two-file mount. After exact-plan approval and pre-apply baseline capture, it modifies only the isolated candidate. [Recipe](../recipes/react-helpdesk/1.1.0/recipe.json) · [Transformation tests](../packages/transformation/test/transformation.test.ts).

**After:** a movable daily assistant, in-chat approval and host administration tab share a governed backend. Users read tickets/members and confirm priority/assignee changes. Current host rights, target versions and exact approval bindings are rechecked; receipts and original host data establish the result. Conversation history and immutable releases have separately qualified persistent paths.

Inspect the [ten-case baseline/delivery](verification/delivery-qualification.md), [OFF/ON business comparison](verification/behavior-improvements.md), [joined PostgreSQL/release/browser journey](verification/joined-release-qualification.md), [conversation browser evidence](verification/conversation-ui.md) and [actual negative faults](../qualification/m1-negative/README.md). These are synthetic business and recovery results, not live-provider benchmarks.

## Python/SQLite inventory: a different domain and language

**Before:** a Python inventory domain reserves quantities for orders, owns current rights and commits stock changes with receipts in SQLite. [Original host](../fixtures/existing-python-inventory).

**AE change:** the same lifecycle captures its original business baseline, then `python-inventory@1.0.0` adds only a standard-library JSON adapter. It does not rewrite the host into TypeScript or duplicate AE's runtime.

**After:** the shared official SDK/runtime can read stock, wait for a precise reservation confirmation, execute once through the Python host and reconcile a lost response. The profile compares 13 independent original/candidate business cases and runs 25 host tests. [Exact lifecycle evidence and reproduction](verification/cross-stack-inventory.md).

A separately composed [inventory UI](../fixtures/inventory-ui) exercises the same generic SDK/HTTP seam: actual sandboxed Chromium confirmation reserves three desks, stock 12 → 9, one mutation, with no external requests. [Screenshots and bounds](verification/generic-host-ui.md). It is not a browser transformation output of the headless recipe and does not claim PostgreSQL inventory history.

## Java/Spring Core: additive lifecycle and remote-MCP qualification

**Before:** the [original Java/Spring Core inventory](../fixtures/existing-java-spring-inventory) has an ordinary stock/reservation CLI and no AE adapter.

**AE change:** `java-spring-inventory@1.0.0` archives 14 original CLI business cases before applying only `agentic/AeHost.java`. Its real public CLI lifecycle verifies original-versus-generated parity, unchanged business/CLI source, eight evidence-tamper negatives, the shared runtime and guarded revert. [Lifecycle evidence](verification/java-spring-recipe.md).

**After:** the generated adapter uses actual Spring-managed beans and the same TypeScript authority/approval/receipt boundary. The independently qualified [Java host and remote-MCP journey](verification/java-spring-remote-mcp.md) covers socket loss after commit, process restart, receipt reconciliation and official authenticated read-only MCP traffic on loopback HTTP.

This exact synthetic Java 21/Spring Core 6.2.19 recipe is not arbitrary Java discovery, Spring Boot/MVC, production IAM/TLS, Java PostgreSQL recovery or an external showcase. The original language and business entry point remain intact.

## Compare integration effort without inventing a speedup

The [paired direct/manual-recipe versus AE measurement](verification/adaptation-costs.md) records equal resulting React/Python bytes, actual modified files/lines, execution times, observed defects/rework and evidence overhead. It uses a scripted already-authored direct patch, not a human productivity study. Both arms pass the same fixture acceptance; AE's measured stage sums are higher and include extra baseline/packaging work. Unknown human, historical and token costs remain unknown.

## Contribute another integration

Start with an ordinary host that does not already contain AE. Document its language/framework, trusted identity boundary, business API, safe reads and approval-requiring effects. Use its own original black-box baseline, reproducible diff, negative cases and guarded rollback. A screenshot or imported component alone does not qualify a new stack. See [contribution criteria](../CONTRIBUTING.md) and the [support matrix](support-matrix.md).
