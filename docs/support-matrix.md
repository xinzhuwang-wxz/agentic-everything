# Declared support and operational ownership

Support is scoped by host/version, surface, capability and environment. A fixture pass does not qualify every host in its language, and a contract experiment is not a deployed platform. [Acceptance status](acceptance-status.md) records the accepted core source and environments; [operations](operations.md) describes installation and recovery.

Other framework/platform layouts receive analysis or reviewed custom-integration guidance (L0/L1), not an automatic recipe success. A new L2 recipe needs its own repeat/rollback/original-business tests; L3 requires the exact host's business, authority and recovery evidence. These support levels describe tested execution maturity, not which kinds of products are allowed to become agentic.

## Optional extensions and exclusions

| Surface | Owner | Declared scope | Evidence / limit |
| --- | --- | --- | --- |
| Automation | Extensions + DBOS/host | One daily local-time cron, IANA zone, bounded validity/lateness, stable occurrence identity, pause/resume/current rights, restart/deduplication | [Local PG evidence](../qualification/extensions/README.md). DBOS is the sole scheduler; no arbitrary cron, permanent background service or real external recurring action is enabled. |
| A2A | Extensions + host authentication | Official SDK 1.3.0/protocol 1.0 JSON-RPC single-text SendMessage/GetTask/CancelTask, scoped auth and existing runtime state | Same report. No streaming, push, task list, file parts, arbitrary peers, in-band approval or multi-turn continuation. |
| Mobile/miniprogram | Host bridge owner | Strict versioned start/status/cancel with trusted session/origin boundary, real governed-runtime fixture | Contract/fixture-only; real device/platform **not-run/unverified**, expressly allowed by plan §15.3. No store release or universal SDK. |
| Knowledge and permanent memory | Not enabled | No ingest/retrieval/embedding engine or permanent memory | No knowledge permission/ingest/revoke claims. Enabling knowledge requires qualification first; permanent memory is excluded from this release. |
| Production identity/deployment/providers | Deployment + host operator | Not enabled by synthetic qualification | Real SSO, credentials, paid inference, customer data and deployment need their corresponding authorization and environment-specific checks. |

Historical component receipts and the final assembled candidate are separate. Follow the acceptance ledger for integration status instead of promoting every row because a unit suite, installer doctor or fixture bundle is green.
